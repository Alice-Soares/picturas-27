# Especificação de Requisitos — Suporte a Vídeo no PictuRAS

**Baseline:** UC-VID-001 a UC-VID-007, versão v1.0, 2026-10-14  
**Âmbito:** MVP de submissão e processamento de vídeo  
**Origem:** casos de uso existentes em `docs/use-cases/`

Este documento consolida os requisitos derivados dos sete casos de uso existentes. A indicação `NOVO` significa que a capacidade não existe no PictuRAS atual; `ALT` significa que uma regra ou mecanismo existente tem de ser estendido para suportar vídeo.

## Cobertura dos casos de uso

Os requisitos específicos de cada caso de uso estão identificados pelo prefixo correspondente. Os requisitos `COM` são transversais e aplicam-se aos casos de processamento que os referenciam.

| Caso de uso | Funcionalidade coberta            | Requisitos específicos    | Requisitos transversais         |
| ----------- | --------------------------------- | ------------------------- | ------------------------------- |
| UC-VID-001  | Submeter vídeo                    | `SUB-001` a `SUB-009`     | `COM-001`, `COM-003`, `COM-004` |
| UC-VID-002  | Recorte temporal                  | `TRIM-001` a `TRIM-006`   | `COM-001` a `COM-004`           |
| UC-VID-003  | Aplicar ferramenta aos fotogramas | `FRM-001` a `FRM-005`     | `COM-001` a `COM-004`           |
| UC-VID-004  | Converter formato e resolução     | `CONV-001` a `CONV-003`   | `COM-001` a `COM-004`           |
| UC-VID-005  | Extrair fotogramas                | `FEX-001` a `FEX-003`     | `COM-001` a `COM-004`           |
| UC-VID-006  | Concatenar vídeos                 | `MERGE-001` a `MERGE-003` | `COM-001` a `COM-004`           |
| UC-VID-007  | Gerir áudio                       | `AUD-001` a `AUD-005`     | `COM-001` a `COM-004`           |

## Decisões e limites mantidos em aberto

As seguintes questões dos casos de uso não foram convertidas em requisitos, por ainda não estarem decididas: substituição ou versionamento do original, retoma de jobs, transições no merge, seleção de múltiplas faixas de áudio, uploads simultâneos e criação automática de miniaturas. Devem permanecer como questões abertas até existir uma decisão explícita da equipa.

## Verificações de cobertura

- Cada requisito tem uma origem num caso de uso, regra, pós-condição ou decisão de qualidade.
- As operações de submissão, trim, fotogramas, conversão, merge e áudio têm requisitos funcionais próprios.
- Falhas, cancelamento, quota, preservação do original e autorização estão cobertos transversalmente.
- O impacto no sistema existente está separado do requisito funcional e identifica os componentes a estender.
- Os valores de limites são os definidos nos casos de uso e no [TODO.md](../TODO.md); devem ser validados pela equipa/docente antes da implementação.
